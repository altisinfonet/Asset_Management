# Contributing rules

How every change to this repository is made, whoever (or whatever) makes it. Read this before starting work.

## Git

- Work on a branch (or an isolated worktree); `main` only receives verified merges.
- Conventional commit messages (`feat(api): …`, `fix(web): …`, `docs: …`, `test: …`, `chore: …`).
- **No AI attribution in commits or PRs**: no `Co-Authored-By` lines, no "generated by" text.
- Use the repository's git identity; do not change git config.
- Commit after each finished piece of work, so an interrupted session loses little.

### Changing the API contract

Edit `docs/engineering/tools/gen.mjs` only (never the yaml by hand), in a clearly commented block for your area,
then regenerate `openapi.yaml`, lint it (`npx -y @redocly/cli@2.79.0 lint docs/engineering/openapi.yaml`,
0 errors) and regenerate the client (`pnpm --filter @assettracker/api-client generate`; its `generate:check`
runs in the tests). Both generators run from a plain checkout after `pnpm install` (`yaml` is a pinned root
devDependency): `node docs/engineering/tools/gen.mjs docs/engineering/openapi.yaml` (the output path is required) and
`node docs/engineering/tools/gen-api-md.mjs` (add `--check` to verify `docs/API.md`; `YAML_DIR` is only a fallback
when `yaml` is not installed). Add new problem codes to both `PROBLEM_CATALOG` (`apps/api/src/platform`) and the contract.

## Database migrations (`apps/api/migrations`)

- Numbered, append-only SQL files. When several changes are developed in parallel, each gets its own reserved
  number range.
- Tenant tables follow the conventions: `create_tenant_table` / `apply_tenant_conventions`, ENABLE + FORCE RLS,
  the NULLIF tenant policy, composite `(tenant_id, id)` foreign keys, and grants on partitioned parents only.
- `app.provision_tenant` may only be replaced starting from its **current** definition (latest migration that
  defines it).
- After a migration: `pnpm --filter @assettracker/api db:pull` (the drift check must stay clean) and
  `schema:lint` must report 0 violations.

## Code rules

- Database access only through `withTenantTx` / `withPreTenantTx` (Prisma Client); raw SQL only as tagged
  `$queryRaw` / `$executeRaw`, never the `*Unsafe` forms. ESLint module boundaries must pass.
- Use the ports (`apps/api/src/ports`): audit and outbox in the same transaction as the change; job payloads
  carry ids only; mail and notifications are sent inside a tenant transaction.
- API conventions: problem+json errors from the catalogue, ETag / If-Match, Idempotency-Key on mutations,
  cursor pagination, permission declared on every route. The route-rules, role-matrix and route-replay
  (tenant isolation) tests must cover every new route.
- Under RLS, `lower()`, `ILIKE`, `@@` and jsonb `@>` cannot use indexes (ADR 0005): use stored key columns with
  btree equality for hot lookups.
- Web: all strings through i18n (`jsx-no-literals`), axe checks in light and dark for new screens, MSW mocks
  that mirror the real API exactly, the static-export guard must pass, typed API client only.

## Verification before merging

1. `pnpm install --frozen-lockfile`.
2. From a clean state (`rm -rf apps/web/next-env.d.ts apps/web/.next apps/api/src/generated apps/api/openapi.generated.json`):
   `pnpm turbo run lint typecheck test build --force` green, and `pnpm format:check` clean.
3. API changes: `docker compose -p <project> up -d --build` (alternate host ports via a git-ignored `.env` if the
   default stack is running) → `/readyz` 200; API e2e in **both** modes with the full environment and 0 skipped:
   `DATABASE_URL` (PgBouncer port for pooled, Postgres port for direct), `ISOLATION_MODE=pooled|direct`,
   `POOLED_ONE_URL` (`…/app_one`), `MIGRATOR_DATABASE_URL`, `ADMIN_DATABASE_URL`, `SMTP_URL`, `MAILPIT_API_URL`,
   `S3_ENDPOINT`, `S3_BUCKET=assettracker-files`, `S3_ACCESS_KEY_ID=minioadmin`,
   `S3_SECRET_ACCESS_KEY=minioadmin-dev`, `S3_CREATE_BUCKET=true`, `CLAMD_HOST`, `CLAMD_PORT`, then
   `pnpm --filter @assettracker/api test:e2e`. Drift check clean. Tear down with `down -v`.
4. Web changes: `PW_CHANNEL=chrome pnpm --filter @assettracker/web test:e2e` passing; real-stack suite
   (`test:e2e:real` with `E2E_API_URL` / `E2E_MAILPIT_URL`) when the change touches real flows.
5. Never touch the founder's running stack (default ports 3000/3001) or its data.
6. On Git Bash, prefix `docker exec`/`cp`/volume paths with `MSYS_NO_PATHCONV=1`.
7. Update the maintained project docs (`API.md`, `FEATURES.md`, `VERSION.md`, `AUDIT.md`, `STATUS.md`) when the
   change affects them.
